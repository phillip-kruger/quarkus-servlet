# TODO: TCK tests quarkus-undertow passes but quarkus-servlet does not

These 36 Jakarta Servlet 6.1.2 TCK tests **pass on the Undertow engine** that `quarkus-undertow`
ships but **fail on this extension**. They are the regression backlog against the implementation
we replace: each is a behaviour the incumbent engine proves is achievable, so every one is a real,
fixable gap rather than an optional feature.

Generated by diffing the two full TCK runs (`tck` real-boot container vs the `tck-undertow` engine
harness). See README `## TCK` -> "Baseline: what the Undertow engine scores".

## How to work one test

The real-boot container resolves each deployment's model per test, so run **online** (no `-o`):

```bash
mvn -Dtck -pl tck verify -Dit.test='<FQCN>#<method>'
```

Fixes go in `runtime/` and `deployment/` (never in the TCK harness). Mark a box `[x]` once the test
passes and the fix is committed. Re-run the full suite (`mvn -Dtck -pl tck verify`) before closing
a group to confirm no regressions.
